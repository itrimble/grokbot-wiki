Local AI

Local AI

Source: /workspace/tailscale/LOCAL-AI.md.

  • oMLX on the Mac mini. OpenAI-compatible /v1. Shared with tailscale serve (tailnet only, no Funnel).
  • Models: Ornith-1.5-9B (main chat, about 17 tok/s), gemma-4-e4b-it-4bit (fast), bge-m3-mlx-8bit (embeddings), Qwen3-TTS.
  • One 9B model at a time. Max 2 concurrent requests. First call loads for about 6 s.
  • Box calls go through the SOCKS5 proxy. The API key is a file on the box: ~/.config/omlx/key. Never print it.
  • Ollama runs on the mini, local only. Reach it over SSH. Models (live check 2026-10-17): qwen3.5:9b, qwen3:8b, qwen3:4b, gemma3:4b, gemma4:e4b. The Qwen3.6-35B line listed earlier is not in the live list (orchestration BOARD.md, audit fix 3).
  • GPU budget on the 16 GB M4 is about 11.3 GiB. Never run local models on the box (no GPU, low RAM).
  • Model routing research and experiments: /workspace/model-orchestration/ (research.md, tracker.csv with EXP-001 to EXP-009, all proposed). Ledger is proposed as owner of the numbers.
  • Caveat: oMLX is not a login item. After a mini reboot run omlx start.
  • From the box, reach it only through the SOCKS5 proxy. A direct call returns nothing (Hermes Tuner audit 2026-10-16). oMLX through the proxy was verified live 2026-10-17 (/workspace/orchestration/BOARD.md).
  • Two key paths, do not mix them up: the box key file at ~/.config/omlx/key exists and works; on the mini, ~/.config/omlx/key is missing and oMLX uses ~/.omlx/settings.json.
  • Mini model storage (2026-10-17): about 104 GB (Ollama ~25 GB, HF cache ~79 GB); about 923 GiB free.
  • Speed numbers above (~17 tok/s, ~6 s load, max 2 concurrent) are documented but not benchmarked.
